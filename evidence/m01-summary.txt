M01 gate 1: complete. GCC 13-win32 i686-w64-mingw32-g++ builds/links PE32
rtl8125.sys with NT native subsystem and actual _DriverEntry@8 entry. Imports
are exclusively ndis.sys, ntoskrnl.exe and hal.dll. No C++ runtime, exception,
RTTI, constructor table or allocating operator new dependency. Link disables
automatic imports, stdcall fixups and pseudo-relocations; no exports required.

M01 gate 2: complete in source and native-ABI fixture. Per-device nonpaged state,
Ethernet-medium selection, allocation failure and probe failure all unwind their
owned resources. A successful PCI/resource/XID probe returns NOT_SUPPORTED and
unwinds too: there is no successful network adapter or packet path. NDIS does
not call Halt after failed Initialize, so Initialize explicitly owns cleanup.

M01 gate 3: complete conservative discovery/OID implementation. Real SDK OIDs,
strict query/set lengths and initialized byte counts; disconnected link, zero
speed/buffer availability, no fabricated MAC, no unsupported offload/power
advertisement, nonzero filters refused. A zero filter/empty multicast state is
accepted only as inactive state; bounded lookahead uses shared frame limits.

M01 gate 4: complete. Genuine ReactOS kernel execution in the isolated owned
guest: two real production DriverEntry/NDIS 5.1 registrations succeed; the actual
production unload handler is checked; 35 labelled kernel callback checks pass
per load; two service load/stop cycles invoke real production wrapper unload;
service deletion and runner end-failures both return zero. The guest-only
anonymous control device makes SCM unload possible under ReactOS policy and is
deleted before delegating to production unload. This fixture is not physical
driver execution or operational PnP Ethernet initialization/removal evidence.

The guest-tested production lifecycle retains its wrapper in an I/O-manager-
owned driver-object extension, registers NdisMRegisterUnloadHandler and calls
NdisTerminateWrapper exactly once on unload. Driver-extension failure cleans
the wrapper before returning from DriverEntry. This fixes the missing wrapper
unload owner found during real guest testing, without mutable global state.
