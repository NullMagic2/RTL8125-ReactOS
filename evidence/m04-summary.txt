Gate 1 source: real NDIS 32-bit DMA setup and checked addresses.
acquire_dma requires PASSIVE_LEVEL and NDIS_ATTRIBUTE_BUS_MASTER. The actual
ReactOS NdisMInitializeScatterGatherDma implementation rejects missing bus-master
attributes; success establishes the actual IoGetDmaAdapter-backed object. The
placeholder scatter/gather list is never consumed. FALSE selects 32-bit DMA,
524288 caps the maximum physical mapping, and every complete logical/CPU range
and pairwise allocation overlap is checked without truncating HighPart. The
NDIS-owned adapter initialization persists through release/reacquire retries.
Do not reconstruct DmaOwner while its NDIS wrapper remains alive.

Gate 2 source: fixed uncached common buffers with inverse unwind.
Separate 256 x 16-byte TX/RX rings and 256 x 2048-byte TX/RX arenas use original
NDIS virtual/logical addresses, lengths and uncached flags on every free. Rings
require 256-byte and arenas 64-byte CPU/bus alignment. Every allocation/address
failure unwinds in reverse order. Bounds are fixed before allocation; no DMA-time
heap allocation or allocating C++ runtime is used. enable_dma_bus_master validates
exact PCI identity, Memory Enable, stopped/reset-clear engines and a well-formed
PCIe endpoint capability with requests drained; writes only the PCI Command word
and verifies all preserved bits and posted MMIO readback. OWN/base exposure is
rejected until that explicit PCI contract succeeds. An uncertain PCI enable
retains buffers and enters controlled retirement rather than trusting its failure.

Gate 3 source: live publication and late completion ownership.
Placement construction begins aligned volatile live-descriptor lifetimes. Data,
logical address and options2 precede the memory barrier and final aligned OWN
store. Completion reads OWN then uses a native barrier and consumes software
pending once. RX payload copying repeats length/error/segmentation/FCS checks.
Retirement latches admission closed before the real lifecycle fence callback;
late OWN publication, completion and payload copying are rejected after failed
retirement too. No offline descriptor image is cast into DMA memory.

Gate 4 source: full A/B drain plus actual platform retirement boundary.
The real M08 callback closes packet/restart admission and joins M07 interrupt,
private KDPC/link work plus recovery/ordinary caller users before hardware I/O.
retire_dma then invokes the shared hardware::quiesce_device sequence, adapted
from pinned Linux v6.12 rtl8169_cleanup, rtl_enable_rxdvgate and
rtl_wait_txrx_fifo_empty. It masks interrupts, rejects RX, gates RXDV and waits
2 ms; A (MAC61) polls MCU RXTX_EMPTY, B (MAC63) first sets StopReq then polls MCU
and the 0x0103 IntrMitigate drain indication. TXCFG_EMPTY belongs to older chips
and is deliberately not substituted. After another 2 ms it resets and polls
reset/RX/TX-enable clear with bounded waits, then commits posted writes. Exact
PCI Command-only bus-master disable/readback and bounded PCIe Device Status
Transactions Pending checks supplement that drain. Transactions Pending covers
nonposted requests only, so it is never treated as proof of posted DMA drain by
itself. Missing/malformed capabilities, changed identity, missing device, reset,
FIFO, fence, readback and timeout failures retain all buffers and packet owners.
Hardware-drain failures still attempt PCI containment, but do not permit a free.
Never-exposed failed starts also disable/read back our PCI enable before release.
All caller HardwareState readiness must be invalidated before the first retirement
attempt, including a failed attempt. No boolean public clear-exposure API exists.
