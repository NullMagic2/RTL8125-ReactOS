Module: rtl8125.evidence.m01_review
Purpose: Record the concrete conservative-OID issue found by the relaunched M01 agent.
Created: 2026-10-24 America/Sao_Paulo
Architecture: Focused query formatting change; M01 gates and original evidence retained.

Finding:
The five general statistics OIDs always returned a 32-bit scalar and 4 bytes
written, including requests with at least 8 bytes of storage. The current probe
has zero counters, so this did not fabricate traffic, but the query contract
could not represent 64-bit statistics and did not report the supported width.

Primary references consulted:
https://learn.microsoft.com/en-us/windows-hardware/drivers/network/querying-64-bit-statistics-oids
https://learn.microsoft.com/en-us/previous-versions/windows/hardware/network/ff550490(v=vs.85)
The former documents counter request negotiation and the gigabit counter-width
requirement; the latter documents the actual NDIS 5 query callback and output
length contract. Modern HLK was not run or claimed as ReactOS compatibility.

Fix:
src/core/oid.hpp/.cpp owns allocation-free copy_counter_information. It emits
explicit little-endian x86 counter bytes, returns low 32 bits for capacity 4..7,
returns all 64 bits for capacity >=8, and rejects capacity <4 without writing.
Valid replies and short-buffer results report a supported width of 8 bytes.
Null nonempty storage is refused. rtl8125_query applies this only to
OID_GEN_XMIT_OK, OID_GEN_RCV_OK, OID_GEN_XMIT_ERROR, OID_GEN_RCV_ERROR and
OID_GEN_RCV_NO_BUFFER. Ethernet alignment/collision OIDs retain 32-bit replies.

  Wine imports are test-only mocks and do not imply guest/hardware execution.
